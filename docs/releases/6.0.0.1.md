# Jvedio 6.0.0.1（Jvedio30.2）/ Connector 0.2.6

本版集中改善 **bus/db 刮削失败的可读性** 与并发稳定性。Connector 插件无变化（沿用 0.2.6）。

## 失败提示：写明「哪个源、哪一环、怎么办」

- **失败自动换源**：单个源刮削失败不再立即终止任务，自动改用下一个启用的源；全部失败时汇总为一条，例如「全部 2 个源均失败：db（javdb.com）：需要登录…；bus（www.busjav…）：页面响应 200 但未找到影片信息…」，每个源的原因也会实时写入刮削日志。
- **错误按环节翻译**：401/登录提示→指引在「选项 → 同步信息」对应服务器的 Headers 粘贴登录后的浏览器请求头（含 cookie）；302→请求过于频繁或需要登录；403/Cloudflare→更新 Cookie/UA 或更换代理；404→番号可能不存在或已下架；超时/无法连接→检查网址、网络与代理；「開通VIP」→需要 JavDB VIP；**200 但无影片信息**→明确提示可能为人机验证页、需要登录或站点改版（此前会误显示为“成功获取资源”）。
- **JavDB 修复误报**：搜索环节的网络异常此前会被吞掉并误报为 404，现在如实标注“搜索页网络请求失败”及原因。
- 每条错误带 `[插件 · 域名]` 前缀，一眼看出是哪个源出错。

## Headers 指引

Headers 弹窗顶部的填写提示此前依赖第三方组件内建文字（一旦缺失即整体消失），现改为写入主程序三语字典，永不再丢失；并按当前行所属插件显示针对性建议——**JavDB 通常需要登录 Cookie**（附失效时的处理方法），**JavBus 一般无需填写**（被拦截时再粘贴浏览器请求头）。「教程」按钮链接仓库内的逐步图解（F12 → Network → Doc → Request Headers），依然有效。

## 稳定性修复

- **并发刮削偶发「集合已修改；可能无法执行枚举操作」**：所有任务此前共用一个静态请求头对象，现改为每个任务独立深拷贝，杜绝跨任务竞态。
- **bus 回传 Referer 覆盖用户 Headers**：你填的 Cookie 可能被悄悄清空——已改为合并而非覆盖。
- 刮削主链路的日志调用加防护（日志竞争最多丢一行日志，不再中断任务）；UrlCode 查询增加瞬态异常重试；插件按 `crawler/db`、`crawler/bus` 正确匹配提示。
- 异常日志改记**完整堆栈**，便于精确定位残余问题。
