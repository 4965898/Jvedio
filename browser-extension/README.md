# Jvedio Connector 0.2.6（随 Jvedio 6.0.0.0 正式发布）

独立的 Chrome Manifest V3 插件，支持 JavBus、JavDB、JAVLibrary。根据页面结构识别镜像站，读取用户当前已加载的页面，不需要在 Jvedio 中重新请求影片详情页。

## 安装与连接

1. 从 [Jvedio 6.0.0.0 发布页](https://github.com/4965898/Jvedio/releases/tag/6.0.0.0) 下载桌面端。首次使用解压 `Jvedio-6.0.0.0.zip`；升级已有完整安装时，先完全退出 Jvedio（包括托盘），备份原 EXE，再把 `Jvedio-6.0.0.0.exe` 改名为 `Jvedio.exe` 放入原安装目录。单独 EXE 需要同目录原有 DLL、爬虫和资源文件。Connector 0.2.6 只调整卡片勾选交互，桌面接收协议未变；已在使用 Jvedio 5.4.1.73 或 0.2.4 配套预览 EXE 的，可只更新插件。
2. 将发布页下载的 `Jvedio-Connector-0.2.6.zip` 解压到固定目录。在 Chrome 打开 `chrome://extensions/`，打开“开发者模式”，点击“加载已解压的扩展程序”，选择包含 `manifest.json` 的文件夹。也可以直接加载本仓库的 `browser-extension` 文件夹。更新已有插件时，用新文件覆盖原插件目录，再在扩展管理页点击重新加载，并确认版本为 0.2.6。站点访问范围未增加；三站已授权的 HTTPS 页面会自动显示卡片按钮。已有页面可先点一次工具栏图标激活新按钮，保留已加载的瀑布流内容；也可刷新网页。
3. 在 Jvedio 打开 **选项 → 扫描与导入 → 浏览器剪藏**，点击“开启接收”，复制连接密钥。默认端口 `18888`；端口被占用时，在此处换用其他端口。
4. 点击 Chrome 插件（或右键图标选择“选择影片库、标记与连接设置…”），展开“连接设置”，填入相同端口及连接密钥，点击“保存设置并连接”。选择目标影片库后保存一次，插件会记住目标库。

密钥与接收开关会保留。密钥在桌面端用 Windows DPAPI 加密；插件在 Chrome 的本地存储中保存密钥。Jvedio 开启接收后，重启软件会自动恢复；关闭选项窗口不影响接收，退出软件会停止接收。主菜单“浏览器剪藏”会直接打开上述设置页。

## 小窗口与选择方式

**列表卡片零散多选：** JavBus、JavDB、JAVLibrary 的番号或日期旁自动出现“＋Jvedio”。逐个点击需要的卡片，按钮变为“已勾选”，不同卡片会累计加入本页选择；**再次点击同一部的按钮即取消勾选**，点错的影片不必再到小窗口里查找。挑选完成后点击工具栏图标，在小窗口选择影片库和标记，再点“保存所选 X 个番号”统一入库。点击卡片按钮不会直接入库、跳转或自动打开窗口；窗口打开后继续点卡片也会同步勾选，在窗口取消勾选会同步更新卡片。瀑布流新增卡片自动补按钮，隐藏原列表不重复装饰。保存仍只使用卡片已有字段和封面，需要完整资料时使用详情页入口。

标准三站域名自动显示按钮；结构兼容的其他镜像站可先点击工具栏图标，通过原有 activeTab 授权启用当前页。勾选不要求先连接桌面端；连接密钥只在扩展后台读取，页面脚本的合成点击不能触发勾选。后台校验主框架、页面地址、当前文档和列表番号，按来源页面串行合并卡片与窗口选择，避免快速点多部影片时互相覆盖。

**列表页点击图标**会打开默认约 **380 × 560** 的独立浏览器小窗口；**单部影片详情页点击图标**直接保存到上次使用的影片库，成功时不会创建或打开选择窗口。首次缺少连接配置、尚未选择影片库、目标库已删除或文字资料保存失败时，再打开小窗口说明原因并供手动处理。

工具栏图标显示“…”表示正在保存、绿色“✓”表示完成、橙色“!”表示需处理或有媒体提示；鼠标悬停图标可查看目标库、番号、保存数量和媒体结果。部分图片或视频无法取得时，已入库的文字资料保留，图标提示具体问题，不打断浏览。需要改库、添加多个标记、查看结果或修改连接时，**右键图标 → 选择影片库、标记与连接设置…**。手动打开窗口不会自动保存，也不会沿用旧版 `autoDetail` 开关触发保存。

拖动系统标题栏移动窗口，拖动边框调整大小；下次打开会记住位置和大小。同一来源标签页已有窗口时复用它。窗口采用系统正常层级，不全局置顶；切回网页或其他程序时可被覆盖，点击窗口外也不会自动关闭。窗口绑定点击时的来源标签页，切换其他标签页不会改变剪藏来源。

**选择仅限当前页面、当前这次挑选。** 没有点击卡片时，新列表默认全部不勾选；先点卡片再首次打开窗口，会带入本次挑选。相同页面内搜索、重复点图标及瀑布流追加保留选择，新增影片默认未选中。手动翻页、刷新网页、点击窗口“刷新”、刷新窗口或关闭窗口均清空勾选，重新打开不恢复旧选择；窗口位置、大小、影片库和标记偏好仍保留。升级会丢弃旧版选择记录。详情页因配置或错误回退到窗口时仍选中本次请求的主影片，窗口不自动再次提交。

“添加标记”位于“保存到”影片库下方、保存按钮上方，使用**多选下拉框**。连接后读取主程序“筛选器 → 标记”的全部定义，包含当前库尚未使用的标记，并沿用筛选器的排序。无需输入或重新创建 AV、套路直播、其他等已有标记。勾选后点击“完成”，也可点框外或按 Esc 关闭；最多选 100 个，“清空”取消选择。新增或改名后点击“连接”刷新。

**此前接入的库内文字“标签”不是这里的筛选器“标记”。** 本版按标记 ID 保存到真正的标记关联；旧标签偏好不会按名称猜测转换，升级后请重新选择一次标记。已有文字标签、影片及原有标记均保留。

标记定义由主程序共用，选择偏好按影片库分别记忆。列表勾选后的统一保存、手动单部及详情页免弹窗均应用目标库已选标记，追加关联并保留已有标记与“新加入”等默认行为。标记改名不会丢失按 ID 保存的选择，同名标记也不会混淆。桌面端在影片事务内回读确认关联，结果显示标记名称及应用影片数量；已删除标记、旧接收端或未确认写入的结果不会显示成功。

## 瀑布流与加载更多

支持用户纠正后的 [JAVBUS封面大图（kygo233/tkjs）](https://github.com/kygo233/tkjs)：该脚本隐藏原列表，将所有后续页转换成 `#grid-b .item-b .box-b` 卡片，原列表通常仍只有 40 部。现在同时读取这些可见新卡片与原列表，按番号去重，读取 `date[name=avid]`、影片链接、标题及懒加载封面。也保留 JAV老司机的 `#waterfall`、`#waterfall_h` 与 `.videos` 容器兼容。

窗口打开时自动识别后续追加内容，保留手动选择，新增影片保持未选中；关闭窗口后停止窗口的数据同步，网页卡片按钮继续自动维护。关闭时清空本次勾选，重新打开读取当时全部已加载内容并默认不选；点击“刷新”也会清空。验证使用 kygo233/tkjs 公开版 20250311 的实际卡片生成函数，以及真实 Chrome 中从 40 部追加到 240 部的保存链路，并独立读取隔离 SQLite 数据库核对每部影片的两个标记。

已加载内容不再截断为前 500 项；大批次保存自动按最多 500 项、低于 1 MB 拆分为接收端事务。后续批次失败时报告此前已完成的条目数量，重试按番号去重。插件不会主动翻页、访问尚未加载的分页或逐条打开详情页。验证未访问用户的登录页面或执行用户脚本的完整网络翻页；用户本机修改及后续在线布局变化仍需实际使用观察。

## 两种剪藏方式

**列表页：** 可先点卡片“＋Jvedio”挑选零散影片，再点插件；也可直接打开窗口，查看本页番号并勾选需要的影片，选择目标库，点击“保存所选番号”。支持搜索、全选和全不选；搜索后的全选/全不选仅作用于当前筛选结果。相同番号自动去重。列表模式保存番号、标题、来源、页面已有的封面/缩略图，以及实际显示的日期或评分。它不逐条打开影片详情页。**按用户决定，批量补齐完整资料暂缓**；页面没有提供的演员、导演等字段不猜测，批量演员图也不从未知影片演员关系推断。

**单部影片详情页：** 识别主影片并忽略推荐列表，抓取原始标题、可用的中文标题、发行日期、时长、导演、制作商/片商、发行商、系列、类别、演员、明确列出的演员别名、评分、评分人数、简介、封面和预览图链接，以及来源网址。网站没有显示的字段留空。

详情页点击图标直接保存，使用上次影片库及该库记住的标记选择；图片与预览视频仍遵循桌面端设置。连续点击正在保存的同一标签页只执行一次操作。需要选标记、清空标记或切换影片库时，通过图标右键进入手动选择窗口。

已有影片的详情剪藏只补全空白字段，保留已有标题、评分、演员等资料。演员别名仅根据网页明确给出的关系匹配。每个来源的原始提取结果保存在 `browser_clip_sources`，不混合不同网站的评分或演员名称。JavDB 的 5 分评分原样保存；JAVLibrary 的 10 分评分换算为 Jvedio 的 5 分制。

在 **选项 → 扫描与导入 → 浏览器剪藏** 中可以分别设置“保存图片”总开关、“保存封面图”“保存预览图”“保存演员图”“保存预览视频”。该区域始终展开，保持白字，并复用设置页的标题、两列布局、输入框和控件间距；浏览器剪藏、扫描、导入的内容列对齐。默认保存封面和可获取的演员图，预览图和预览视频默认关闭。

图片由 Chrome 在浏览器会话中取得，按指定来源请求，再把图片字节发送到本机保存。Cookie 和登录凭据不发送给 Jvedio。封面会写入海报和缩略图目录；演员图使用已确认的演员关联保存，明确列出的历史别名也可用于匹配，不能把照片写到无关演员。详情页没有直接给头像时，会尝试同站演员页中明确的头像区域；站点未提供、页面被验证拦截或无法匹配身份时，选择窗口或图标悬停提示会报告缺失或失败，不假报保存成功。结果页没有演员字段时不抓演员图。

剪藏媒体选项独立于常规刮削设置；修改后对后续剪藏生效，不删除已有文件或中止之前排入的任务。图片完成、失败与缺少头像来源的数量在选择窗口或图标悬停提示中显示；已有图片保留，保存后更新图片缓存和索引。影片尚无本地文件且图片路径设置为“相对影片”时，图片回退到软件数据目录。

文本资料先完成入库，图片随后在浏览器后台处理。预览视频使用 Jvedio 的下载任务，保存在影片的预览目录（`preview-video-1.mp4` 等），支持当前页面可取得的 MP4/WebM 直链，单个文件上限 250 MB。JavDB 的延迟加载接口由浏览器使用当前网站会话读取；不能取得的地址会提示，文字资料仍保存。HLS 清单、受 DRM 保护的视频以及需要额外权限而无法取得的预告暂不下载。不会下载影片正片或磁力链接。

已有媒体任务正在运行时会提示；任务结束后再剪藏，可以按新选项排入媒体任务。图片或视频下载失败可在任务页查看并重试。浏览器工具栏图标、扩展管理图标和弹窗图标均复用 Jvedio 桌面端图标。

Jvedio 未运行时仍能勾选并复制番号，或者导出 TXT / JSON。JSON 包含详情元数据和来源；TXT 每行一个番号。

## 当前范围

- 支持本机 SQLite 影片库，不支持 MySQL、图片库、漫画库或游戏库。
- 读取来源页已加载的影片，包括瀑布流追加项；不会主动遍历分页。单个接收事务最多 500 项，大批次由插件拆分。
- 详情自动保存的前提是已连接 Jvedio，且上次使用的影片库仍存在。
- 官网或镜像站大幅更改 DOM 后可能需要更新适配器。当前六个用户提供的 HTML 样本已验证；在线站点的登录状态、人机验证和后续布局变化仍需实用观察。
- Connector 0.2.5 随 Jvedio 5.4.1.73 发布，旧版 0.1.2 随 5.4.1.70 提供。通过开发者模式安装，尚未上架 Chrome 网上应用店。

0.1.1 补充了详情页适配：JavBus 可交叉读取识别码、影片地址与主标题，容忍复制按钮、空格和部分翻译后的字段；JAVLibrary 标题从主标题节点及页面标题读取，兼容缺少书签链接的页面。

插件运行时无需 npm 或第三方依赖。DOM 测试使用 jsdom，实际用户脚本卡片生成测试使用 jQuery。浏览器 SQLite 核对使用 Node 内置 `node:sqlite`，本次验证环境为 Node 24。

```powershell
npm install

cd ..
./scripts/test-browser-clipper.ps1 -ReferenceDirectory '<.NET Framework 4.7.2 reference assemblies>'
./scripts/pack-browser-clipper.ps1
```

设置 `JVEDIO_COVER_SCRIPT` 为本机下载的 `JAVBUS封面大图.user.js` 路径时，`tests/cover-fixture.cjs` 直接调用它的纯卡片生成函数；不执行脚本启动、GM API 或网络操作。未提供时使用同结构的固定测试卡片。原始脚本只留在忽略的测试目录，不随插件打包。

六个源代码文件只在本机读入，原始 HTML（可能含网站会话信息）不放入插件或安装包。测试使用独立数据库，不修改用户影片库。

浏览器集成测试使用单独的临时浏览器配置，加载真实插件并连接隔离的 WPF 接收端；测试调用工具栏处理函数并传入来源标签页，窗口创建/复用/缩放、脚本注入、消息传递、存储和 HTTP 请求均使用真实扩展 API。覆盖详情页免弹窗保存、图标结果、配置缺失/无目标库/目标库删除/桌面离线时的窗口回退及恢复，以及列表默认不选、多标记、窗口非全局置顶、动态追加与图片/视频链路。`tests/browser.cjs` 需要 Playwright，并由 `test-browser-clipper.ps1 -Serve` 提供临时接收端。

实现参考：[Chrome activeTab](https://developer.chrome.com/docs/extensions/develop/concepts/activeTab)、[脚本注入](https://developer.chrome.com/docs/extensions/reference/api/scripting)、[扩展跨域请求](https://developer.chrome.com/docs/extensions/develop/concepts/network-requests)、[扩展会话 Cookie 规则](https://developer.chrome.com/docs/extensions/develop/concepts/storage-and-cookies)。图片访问权限限定为本机接收端、三站、JDBStatic、DMM 与 Pixhost；没有申请所有网站权限。临时来源请求规则只匹配本扩展发起的单个图片地址，完成后撤销。

## 接收协议

- `GET /v1/status`：返回影片库及当前库，`markImport: true`、`markImportVersion: 1` 和顶层 `marks: [{id,name}]`。标记读取 `common_tagstamp`，包含未使用定义，排序与筛选器一致，独立于每库的文字标签。
- `POST /v1/clips`：接收 `{libraryId, site, kind, pageUrl, items, markIds?}`，返回 `{added, updated, skipped, marksApplied, markedItems, imagesQueued}`。最多 100 个标记 ID，校验定义存在，与影片同事务追加到 `metadata_to_tagstamp`，逐部回读确认；缺失定义或漏写则回滚。`marksApplied` 为确认标记数，`markedItems` 为确认影片数。旧 `labels` 协议仅向后兼容旧插件，本版选择和保存不再使用它。
- `POST /v1/images`：接收已保存影片及关联演员的图片字节，校验库范围、保存开关、图片格式及大小，写入本机图片目录。
- 请求必须携带 `X-Jvedio-Token`。只监听 `127.0.0.1`；普通网站 Origin 被拒绝。元数据上限 1 MB，独立图片请求上限 16 MB；一批元数据在一个事务中保存。

## 文件

- `extractor.js`：三站列表与详情适配。
- `card-buttons.js`：三站原生卡片及封面大图卡片的累计勾选按钮；自动跟随新增节点，不改变原有提取结果。
- `watch.js`：窗口连接期间观察来源页 DOM，关闭窗口后停止。
- `popup.html` / `popup.js` / `popup.css`：选择、元数据预览、库选择、复制和导出。
- `background.js`：原生小窗口创建与位置大小记忆、当前页选择合并与清空、分批接收端连接；弹窗关闭后保存请求仍由后台完成。
- `../Jvedio-WPF/Jvedio/Core/Services/BrowserClipperService.cs`：本机接收、校验、事务入库、资料补全与图片队列。
